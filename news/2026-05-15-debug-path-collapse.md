# 2026-05-15：素材｜一个二十多年老兵的忧心——那条从 Debug 开始走向资深工程师的路，正在崩塌

来源：InfoQ 微信公众号，作者署名"灯火明"，编辑蔡芳芳。文章接续 InfoQ 此前对微软 Azure CTO Mark Russinovich 等人研究的报道《微软警告称，AI 正在掏空初级开发者的培养渠道》，从一线工程师的视角对"AI 抽走初级训练场"问题作出回响。归档原因：与本仓库正在追踪的 AIM4SD / 工程教育议题直接相关。

## 核心论点（作者原文复述）

- AI 编程工具最先压缩的，恰恰是高确定性、高重复性、但对初级工程师训练密度最高的任务（Bug 修复、文档、简单模块）。
- 单个公司"少招初级 + 资深 + AI + 外包"在短期 ROI 上理性，但所有公司都这么做就会导致行业人才管线断裂。
- 大厂仍可能保留实习生 / 应届生培养，但初级岗位门槛被显著抬高——要求新人入职时就具备接近中级的判断力。
- 行业人才成熟周期整体前移：未来从事计算机行业的人，可能像艺术生一样需要从小开始接受专业训练。
- "AI 降低的是写代码的门槛，但抬高的是成为职业程序员的门槛。"
- 高等教育压力骤增：原本由企业承担的工程训练（陌生代码库阅读、故障复现、PR/Review、事故复盘）需要被模拟进课程，但教育变革速度远滞后于工业。
- 学术界已经出现错位：研究生依赖 LLM 生成实验代码，但读不懂、debug 不了，最后只能甩给导师；而 debug 能力是计算机这类实验科学可信度的一部分，silent bug 可能让整篇论文结论错误。
- 未来培养机制可能需要"多方共同承担"：大学训练到可学徒化水平 + 企业少而精的培养计划 + 开源社区真实协作 + AI 工具个性化辅导 + 资深工程师把判断力传下去。
- 对个人的建议：尽早起步、大学前打基础、大学期间产出可见作品或参与研究 / 开源，"3 年实际开发经验"将成为区分业余与专业的及格线。
- 落点："只有拥有过真实的'背锅经历'（需求变化、系统故障、线上事故、拉通对齐、清理屎山等等），才能真正从初级成长为资深，而这些经历是任何 prompt 都给不了的。"
