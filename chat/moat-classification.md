# 45 场景 × 护城河类型 交叉分类

> 本文件是 [AIKnowledgeLabor.md](AIKnowledgeLabor.md) §3.2.1.1「需求的经济性分类」中 C 类护城河类型学的配套明细。
>
> 方法：由六名评审Agent各执C1～C6其中一种护城河视角，独立通读 §3.2.1.2–§3.2.1.5 的 45 个场景，对每个场景给出主归属判断，并建议遗漏的新分类，最后人工将判断投票和新建议汇总映射为C1～C7。判据：「假设人人都有免费天才模型，这门生意还在不在？在=真 C，不在=B」。
>
> 七类护城河：C1 担责兜底 / C2 持牌·授权签字 / C3 数据网络·独占输入 / C4 双边归集 / C5 归集即立案 / C6 中立鉴真 / C7 纵向数据锁定。

---

## 一、总体结论

1. **「绝大多数落在 B 与 C」被证实**：45 个里约 **17 个是纯 B**（自助、无护城河）、**3–5 个偏 A**（大企业自建）、**约 22 个是真 C**，分散在 C1–C7，且大量是多护城河叠加。
2. **C7 纵向数据锁定是真 C 的第七种护城河**，独立于 C1–C6——多视角评审在 #8、#12、#19、#21 上收敛于此（对单用户跨时间数据的锁定，详见第四节）。
3. **C2、C3 各覆盖一个易混的近邻**：C2 除个人牌照外也涵盖组织层面的制度授权（同属"须有法定资格者签字才生效"）；C3 除多方网络数据外也涵盖单源独占输入（同属"别人拿不到的数据"）。专有生态 / IP 锁定则属 A（大厂自建），不构成独立 C 类。
4. **真 C 极少是单一护城河**。最强的几个都是叠加：医疗类=C1+C2(+C3/C4)、维权类=C5+C6(+C1)、合规类=C3+C1。护城河应允许"主+次"标注，而非互斥单选。
5. **多名评审反复点出同一批"B 假扮 C"**：#3 法律翻译、#32 养老金、#37 综述、#40/#45 若只做"查规则"——只有叠加担责/归集/持牌才升 C，否则塌回 B。

## 四、各类边界辨析

C7 与其近邻 C2、C3 容易混，以下四条边界划清归属。

### C7 纵向数据锁定，独立于 C3
- **定义**：护城河来自对**同一用户跨时间**的连续行为/认知数据积累——学习轨迹、用药依从史、口味-生物反应档案。越用越准，切换成本极高（个人档案留在平台里）。
- **与 C3 的判据**：C3 的数据在用户离开后对所有人仍有价值（反诈联防、行业基准，横向跨买家）；C7 的数据主要对该用户本人有价值（个人档案，纵向深耕单人）。机制不同，故分立。
- **"剥离 AI"检验**：通过——免费天才模型没有你过去 18 个月的提交记录/血糖曲线。
- 落点：#8（主）、#12、#19、#21（次）。

### 组织授权属 C2
- 制度授权（被公权力/行业联盟授予的规则制定权或法定背书）与 C2 同源——都是"输出须有法定资格者签字/盖章才生效"，只是资格持有者从个人执业牌照扩展到组织。故 C2 定义为「持牌·授权签字」。
- 落点：#39（组织授权变体）。

### 独占输入属 C3
- 对单一稀缺源的独家访问（独家数字化语料、退休老师傅未公开的维修日志）与 C3 同源——都是"个体拿不到的数据"，只是来源从多方汇集变为单源独占。故 C3 定义为「数据网络·独占输入」。
- 落点：#38、#43 的独占语料/隐性知识。

### 专有生态 / IP 锁定属 A，不是 C
- 对专有软件格式/平台 API/世界观 IP 的接入锁定（#10 CAD 格式、#17 游戏 IP），掌握生态的通常是大厂自己，属 A 大企业自建；只有第三方靠授权切入才勉强算 C，过于边缘，不单列为 C 类。

## 五、尚未列入的候选场景（按护城河聚合）

> 均为需求原型，若要入正文需逐个核实真实公司 + 补 IEEE 引用。

**C1 担责兜底**
- 临床试验知情同意（ICF）核查员——核查遗漏致告知不足，平台担责。
- 跨境遗产继承/海外账户解冻代理——按"成功执行"收费 + 错误兜底保险。
- 中小企业出口信用险自动核保 + 违约国际追偿（C1+C5）。
- 医疗账单逐行纠错 + 过度收费追偿（#31 的医疗垂直版，追回分成）。

**C2 持牌·授权签字**
- 小型保险/养老金的精算报告签字（Appointed Actuary 法定署名）。
- 境外上市 PRC 法律意见书（备案合伙人签字）。
- 建筑竣工验收/消防结构复核签章（RA/PE 盖章，规模远大于法律文件）。
- 医疗器械 510(k)/CE MDR 技术文档代备案（RA 署名）。

**C3 数据网络·独占输入**
- 跨机构转诊匹配评分网络（多院用药/过敏/诊断路径汇聚）。
- 中小企业 B2B 赊购信用评分网络（"对手在别家的付款行为"——Credit Bureau 的 B2B 版）。
- 工业设备能耗异常跨厂基准网络（同型号跨厂能耗对标）。
- 跨平台内容侵权"合理赔偿定价"数据库（汇集授权成交价）。

**C4 双边归集**
- 零工执照医生医疗匹配后台（碎片时间医生 × 非急诊咨询需求）。
- 分散制造产能撮合（制造版 Airbnb：闲置产能 × 长尾小批量）。
- 遗嘱执行人 × 受益人清算撮合平台。
- 房客/业主协会集体谈判后台（C4+C5）。

**C5 归集即立案**
- 平台算法投诉集体维权（数万同损用户 → 批量监管立案）。
- 药品/器械不良反应集体报告（散落社群 → 达统计阈值触发强制审查）。
- 小房东对抗平台格式条款集体仲裁（mass arbitration，AAA/JAMS）。
- 消费贷/学生贷系统性违规集体追偿。

**C6 中立鉴真**
- 二手奢侈品/收藏品 AI 鉴真（Entrupy 雏形，护城河在"谁来盖章"）。
- 平台劳工评级中立核查（工会/政府/三方共认的评级审计）。
- AI 诊断的独立第二意见核验（C6+C2 双护城河）。
- 学术论文/数据真实性存证核查（PubPeer 的 AI 版）。

**C7 纵向数据锁定**
- 个人终身职业能力档案教练（跨年记录技能轨迹，换平台＝丢档案）。
- 慢病/术后长期康复纵向管理（个人基线越长越准）。
- 个人精准营养/代谢档案（连续生物反应数据，迁移成本极高）。
