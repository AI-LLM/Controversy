# 从手工记账到 AI Agent：用不可靠单元得到可靠结果的五个元模式

**Date:** 2026-06-05
**Source:** 与 Gemini 的一次对话，[gemini.google.com](https://gemini.google.com/app/dda98a56adff04a3)
**类型:** 想法 / 观点（由对话稿整理、提炼模式、做三代对照）

## 用户的核心立场

从"没有电脑之前银行如何保证手工账目正确"这个问题出发，逐步抽象出一个跨学科命题：

> **单元的不可靠是常态，系统的可靠是设计出来的。**

会疲劳、会粗心、会作弊的人脑，是极不可靠的计算单元；但手工时代的银行靠一套"手动容错与校验系统"建立了极可靠的金融信用。把这套智慧抽离出来，得到的是一组"用不可靠计算单元得到可靠结果"的元模式——它同样适用于分布式系统、容错架构，以及今天会"幻觉"、输出不稳定的 LLM。

对话中用户对 Gemini 的归纳做了两处关键修正，这是用户自己的判断而非 Gemini 的原始表述：

- **"代数特征校验"并不全是代数。** 它混合了数论（同余）、布尔代数（异或/奇偶）、几何拓扑乃至物理材料特性，本质不是"代数"而是"利用某种不变性做低成本校验"。
- **校验指纹不必是数学的。** 物理几何、材料相变、空间容积、光学干涉这些"非数学指纹"同样能从不可靠单元里榨出可靠结果。据此把这个模式正式改名为 **不对称低成本特征指纹（Asymmetric Low-Cost Feature Fingerprinting, ALFF）**——"不对称"指正向制造/计算极难、逆向校验极易；"低成本"指部署代价极小；"特征指纹"指一种无法伪造的物理或逻辑印记。

## 展开：五个元模式 × 三代对照

下表按"人工（手工银行 / 手工业）→ 经典计算机科学 → LLM AI"三代展开。手工与经典 CS 两列是对话中的事实性映射；**LLM AI 一列多为本人/对话末尾的推断性映射，属解读**，标注 ⚠。

### 模式一：对称冗余与状态碰撞（Redundancy & State Reconciliation）

让两组或多组独立的不可靠计算沿不同路径演进，在某点做"状态碰撞"；若结果一致，可靠性指数级上升。

| 人工 | 经典计算机科学 | LLM AI ⚠ |
| --- | --- | --- |
| 复式记账法：每笔交易同时记借方与贷方，收盘时 $\sum\text{借}=\sum\text{贷}$ 才算平；算盘盲算安排两人各打一遍核对 | 分布式共识（Paxos / Raft）多节点投票；三模冗余（TMR）三芯片跑同一代码、2 对 1 多数表决对抗宇宙射线 | Self-consistency / majority voting：同一问题多次独立采样取多数派；多 Agent 辩论；MoE 多专家 |

### 模式二：多维度解耦与交叉审计（Orthogonal Cross-Check）

把全局数据切成互为正交的多个维度分别记录。局部可以出错，但局部错误无法在所有维度里完美自洽。

| 人工 | 经典计算机科学 | LLM AI ⚠ |
| --- | --- | --- |
| 流水账（时间轴）、分户账（客户轴）、总账（分类轴）由不同人登记；分户账余额之和必须等于总账 | 区块链 + Merkle Tree：交易既在区块链条中、又在哈希树中，任一叶子被改则根哈希失效 | 用不同 prompt / 不同模型 / 不同模态独立得出答案再比对；生成结论与检索到的事实交叉核对 |

### 模式三：不对称低成本特征指纹（Asymmetric Low-Cost Feature Fingerprinting, ALFF）

不保证计算过程 100% 正确，而是给数据/状态附一个"指纹"——正向生成极难、逆向校验极易。指纹既可以是数学不变性，也可以是物理印记。

| 子类 | 人工 | 经典计算机科学 | LLM AI ⚠ |
| --- | --- | --- | --- |
| 数论 / 逻辑不变性 | 九除法（Cast Out Nines）：差额能被 9 整除即提示"数字颠倒"，利用 原数 ≡ 各位数字之和 (mod 9) | 奇偶校验位 / CRC / 异或校验；银行卡号、身份证末位 Luhn 算法 | 结构化输出（JSON / Schema mode）+ 类型/正则校验；**单元测试**——写代码难、跑测试一秒出绿/红，正反极不对称 |
| 物理几何（互补排他） | 榫卯结构 | 防呆接口（Type-C / SIM 卡槽缺口）、加油枪粗细不同——插错物理上根本通不过 | （类比）工具调用的参数 schema 约束：不合规的调用根本无法被执行 |
| 材料相变（不可逆） | — | 疫苗温度时间标签（VVM）超温变黑、电力示温蜡片过热塌陷——看一眼即知 | （类比）一次性 / 不可逆的状态标记，篡改即暴露 |
| 空间容积（定额守恒） | 手术室纱布点数盘、工厂阴阳工具板——不数数，只看"有没有空位" | — | （类比）配额/预算钳制：把"计数"降级为"边界是否填满" |
| 光学干涉（误差放大） | — | 莫尔条纹（Moiré）：精密装配 / 印刷防伪，微米级错位被放大成肉眼可见的杂乱图案 | （类比）把难以察觉的细微偏差放大为显眼信号再供人/程序判别 |

模式三的底层心法（用户提炼）：**降低对执行主体的智能要求**——把"思考、计算、回忆"降级为"插得进/插不进""变色/没变色""有空位/没空位"的极简反馈；**借自然的不可逆性**——物理定律、热力学第二定律不会叛变，火漆碎了拼不回去。

### 模式四：职责分离与动态阻尼（Circuit Breaker & Air Gap）

计算链条不能无限拉长，引入"人防"与"物理阻尼"，把错误锁死在最小局部，防止级联失效。

| 人工 | 经典计算机科学 | LLM AI ⚠ |
| --- | --- | --- |
| 钱账分管（出纳不碰账、会计不碰钱）；双人临柜，一人经办一人复核签字 | 代码审查 + 双人授权 / 2FA；微服务熔断器（Circuit Breaker）频繁报错即切断链路 | 生成代码先 sandbox 隔离再跑；关键动作 human-in-the-loop 审批；Agent 工具权限边界 / guardrails，不让模型直接执行高危操作 |

### 模式五：基于日志的可追溯重演（Write-Ahead Logging / Event Sourcing）

只要保留最原始、不可篡改的"发生事实"（Append-Only Log），即便后续所有计算崩溃，也能从头重演、恢复正确结果。

| 人工 | 经典计算机科学 | LLM AI ⚠ |
| --- | --- | --- |
| 铁柜里的原始凭证（字据、划拨单、存折墨迹）：账本算烂了，把原始字据翻出来重拨一遍即可重建资产状态 | 数据库 WAL（预写日志）与 Event Sourcing：先写日志后改数据，断电后重放日志恢复状态 | 完整保留 prompt + tool-call trace 作为可重放事件日志；RAG 以原始文档为 source of truth；保留原始 context 以便重新推理 |

## 一句话脉络

手工时代→经典 CS→LLM 三代，应对"不可靠单元"的工程思路一脉相承：**冗余、碰撞、校验、隔离、追溯**。变的是单元的形态（账房先生 → 芯片/节点 → 概率性的语言模型），不变的是"不去追求完美的执行单元，而去设计一个一旦出错代价立刻暴露的环境边界"。把可靠性寄托在物理定律、数学定理这些"永不叛变"的底层基石上，用最廉价的沙子筑最坚固的防线。
