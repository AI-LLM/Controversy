# 软件股若改造成"卖 AI 劳动力"会落进哪一类（2026-05-30）

> 取 [美股软件股近期重挫 (2026-05-13).md](美股软件股近期重挫%20(2026-05-13).md) 的**企业列表**（仅用名单与各家业务，不引用该文其余分析），套用 [AIKnowledgeLabor.md](AIKnowledgeLabor.md) §3.2.1.1 的 A/B/C + 七类护城河框架（明细见 [moat-classification.md](moat-classification.md)）。
>
> **重构问题**：这些公司过去卖"席位 + UI"。若把旧业务改造成卖"AI 劳动力做完的活/结果"，它会进入哪一类——靠哪种 C 护城河守住，还是只剩一层 UI、塌向 B 被通用 Agent 直接绕过？

## 框架与重构判据

- **A 大企业自建 / 深度锁定**：需求集中在大组织内部，靠 system-of-record 深嵌、迁移成本极高守住。
- **B 个体自助（被去中介化）**：需求分散且无残余护城河，价值只剩"会用模型推理"——通用 Agent 一来就被绕过。**这是 SaaSpocalypse 的靶心**。
- **C 代理归集成生意**，七种护城河：C1 担责兜底 / C2 持牌·授权签字 / C3 数据网络·独占输入 / C4 双边归集 / C5 归集即立案 / C6 中立鉴真 / C7 纵向数据锁定。
- **判据（剥离 AI）**：假设人人都有免费天才 Agent，这家公司卖的东西还剩什么？剩护城河 → 守得住的 C/A；只剩"那层操作界面" → 塌 B。
- **另有一类不在 A/B/C 里**：**基础设施"卖铲子"**——它不是知识劳动力，而是 AI 劳动力运行其上的"骨骼"（算力、数据、网络、安全身份）。AI 劳动力越多，它越被消耗。

## 分组解读

### 一、塌向 B：只剩"那层 UI"，被 Agent 直接绕过
**ASAN / MNDY / SMAR / TEAM / GTLB / PEGA / HUBS / BRZE。** 它们卖的核心价值是"一个让人协调工作的界面"。剥离 AI 后什么都不剩——通用 Agent 直接读写底层数据、自己排期派单写文档，根本不需要中间这层界面。这类是 SaaSpocalypse 最直接的靶心：**护城河等于零，所以模型越强它越薄**。能不能自救，取决于能不能往下一格抓住数据（C3）或往上抓住信任，否则只能塌。

### 二、System of Record / 数据重力：C3（+A）
**SAP / ORCL / NOW / WDAY / CRM / PLTR。** 它们真正的护城河从来不是 UI，而是**"那份别人拿不到、且 AI 必须写回去的企业数据"**（C3 独占输入）+ 深度集成造成的迁移成本（A 锁定）。改造后它们卖的是"可审计的写入端 / 决策端"——Agent 越多，越需要一个可信的落账点，核心反而被**加固**。但挂在核心外围的按席位模块（SAP 的 Concur/SuccessFactors、Salesforce 的销售席位、Workday 的分析席位）没有这层保护，照样塌 B。这解释了它们"跌但没崩"的中间态。

### 三、双边网络：C4
**TOST / PCOR / BILL / APP（+ Ariba 类）。** 护城河是**同时归集了供需两侧**：Toast 攥着餐厅 × 支付、Procore 攥着总包 × 分包 × 业主、BILL 攥着 SMB × 其供应商付款网络、AppLovin 攥着广告主 × 发行商。Agent 能替代里面的工作流，但替代不了"两侧都已经在这张网上"的跨边网络效应。改造后它们把 Agent 嵌进网络做撮合/自动化，网络本身仍是壁垒。AppLovin 是最纯的赢家样本（C3 广告数据 + C4 市场双护城河）。

### 四、信任 / 合规 / 担责：C6 · C2 · C1
- **OKTA / TENB / DOCU**：身份认证、漏洞核验、合同存证——本质都是**中立第三方出具可被各方采信的核验（C6）**，Agent 再强也得有人盖这个章。Okta 因此是抗跌赢家。
- **CRWD / S / ZS / FTNT**：安全的护城河是**威胁数据网络（C3，越多端点越准）+ 为漏防担责（C1）**——AI 不能在"被攻破我赔"的承诺上签字。所以安全板块整体跌幅远小于应用层。
- **VEEV / SNPS / CDNS**：垂直监管 / 认证流程（C2）+ 行业独占数据（C3）。Veeva 的 GxP 验证、EDA 的代工认证流程，都是"必须由被授权体系签字才生效"——监管护城河跟模型强弱无关。
- **ADBE**：是这组里最摇摆的。创意工具本体高度暴露于生成式 AI（塌 B 风险，YTD −31%），但 Firefly 的**商用版权赔付（C1）+ Content Credentials 来源凭证（C6）**是一条真出路——前提是它把价值从"工具"挪到"可放心商用的担保层"。

### 五、基础设施"卖铲子"：AI 劳动力的骨骼，不在 A/B/C 里
**SNOW / MDB / CFLT / DDOG / NET / FSLY / AKAM / DOCN / MSFT/ORCL/SNPS 的底座部分。** 它们不是知识劳动力，是 AI 劳动力**运行其上的算力、数据、网络、可观测性**。AI 劳动力越泛滥，骨骼被消耗得越多——所以这一格几乎全是抗跌或上涨（FSLY +147、APP +89、OKTA/NET/DDOG +30 档、SNOW 基本持平）。其中数据底座（SNOW/MDB）还额外占着 C3 数据重力：企业数据在哪，AI 劳动力的独占输入就在哪。Cloudflare 的 pay-per-crawl 更进一步——直接演化出"向 Agent 流量收过路费"的新 C4 tollbooth。

### 六、平台巨头：A / 聚合者之王
**MSFT（+ ORCL）。** Copilot 是企业默认 Agent 入口，靠的是企业全栈锁定（A）+ 自有云底座（基础设施）。它不靠单一护城河，而是把上面五类同时占一部分——所以回撤最浅（−22%）。

## 框架 vs 股价：一次顺带的验证

把"进入类型"与名单里的跌幅并排，相关性很直接：

- **塌 B 组**（ASAN −50、DOCU −52、HUBS −51、MNDY/SMAR −39、GTLB/TEAM/PEGA/BRZE 深跌）= **跌得最狠**。
- **守得住的 C / 骨骼组**（SNOW ≈0、OKTA +35、NET +30、DDOG +30、APP +89、FSLY +147、CRWD −16、SNPS −11、CDNS −8）= **抗跌或上涨**。
- **System-of-Record 中间态**（SAP −38、NOW −40、CRM −31、WDAY −40、VEEV −37）= **跌但没崩**——正是"核心守得住、外围席位塌 B"两股力量相抵的定价。

也就是说，**市场这半年在做的，本质就是按"剥离 AI 后还剩什么护城河"给软件股重新排座次**——这恰好是本框架 B vs C 的判据。框架预测的塌 B 名单，与跌幅最深的名单高度重合。

## 几条判断

1. **"卖席位"≈ 押注 B，"卖护城河"≈ 守住 C**。同样被 Agent 冲击，结局取决于剥离 AI 后手里还攥着什么：数据（C3）、网络（C4）、信任/合规/担责（C6/C2/C1）、还是只剩一层界面。
2. **多数 system-of-record 公司不会整体塌，但会"瘦身"**：核心写入端加固，外围按席位模块塌 B。它们的改造任务是把计价从"席位"换成"per-outcome/per-token"，把价值显性地钉在护城河那一格。
3. **最干净的赢家是骨骼层和数据/网络层**——它们被 AI 劳动力消耗而非替代，所以是结构性受益方，而不只是"少跌"。
4. **垂直 + 监管 = 天然抗体**：Veeva、EDA 这类靠 C2/C3 的，受冲击最小；通用、水平、无合规壁垒的工作流 SaaS 受冲击最大。
